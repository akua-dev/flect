# Flect v0.1 launch design

## Status

Approved for implementation on 2026-07-30.

## Outcome

Flect v0.1.0 is the first public build that another person can understand,
install, run, and evaluate without private context. The release must make the
current protected vertical slice feel coherent and deliberate:

- a high-quality agent composer that works in the browser and native host;
- real interface shaping, rollback, safe-mode, and model-selection actions;
- an Apple Silicon macOS package and a browser/source quickstart;
- repository media captured from the verified product rather than a mockup;
- an honest statement of the current signing and platform boundary; and
- one reviewed commit history merged to `main` and tagged `v0.1.0`.

The release is a public developer preview. It is not presented as Flect 1.0 or
as proof that arbitrary imported interfaces, capsules, product capabilities,
signing, notarization, or the full sharing ecosystem already exist.

## Product strategy

The first release adopts the interaction quality of T3 Code's composer without
copying its product model or importing its full editor architecture.

The useful T3 Code patterns are:

- one stable composer surface before, during, and after a turn;
- an input that grows with the draft and becomes scrollable at a bounded
  height;
- deliberate keyboard, IME, focus, send, stop, disabled, and busy behavior;
- a footer that keeps the most important controls visible and compacts cleanly;
- a real model picker whose selected state is obvious; and
- contextual commands that expose real capabilities instead of ornamental
  controls.

Flect does not need T3 Code's Lexical editor, file mentions, provider skills,
terminal contexts, image pipeline, thread stash, plan workflow, approvals, or
mobile-specific composer state in this release. Those features depend on
capabilities Flect has not shipped. Pulling in their UI would make the shell
look more capable than it is and would add a large dependency for no current
product value.

## Composer experience

### Working surface

The composer remains the visual center of the empty launcher and the stable
bottom instrument once a conversation starts. It uses Flect's existing
"Midnight Drafting Desk" tokens:

- `surface` at rest;
- one precise rose focus seam and the documented prompt lift while focused;
- Ink for the enabled primary action;
- Failure Red for stop only;
- tonal hover states instead of decorative borders; and
- 150–200 ms state transitions with a reduced-motion fallback.

The textarea starts at one comfortable line, grows up to six lines, and then
scrolls. Enter sends, Shift+Enter inserts a line break, and active IME
composition never submits. Submitting an empty draft is impossible. The draft
clears only after a send is admitted, and failures retain a retry path through
the existing session controller.

### Footer

The left footer contains:

1. an Actions control;
2. the current Pi model; and
3. a concise `via Pi` source label when width permits.

The right footer contains one primary control that changes from Send to Stop.
It exposes an accurate accessible name for booting, setup, unavailable,
sending, streaming, cancelling, and ready states.

At compact widths, labels collapse before actions disappear. All controls keep
at least a 44 × 44 CSS-pixel touch target.

### Actions menu

The Actions control opens a keyboard-operable popover with only implemented
commands:

- **Shape interface** opens the protected Interface Shaper;
- **Roll back last change** invokes deterministic rollback when a prior
  accepted revision exists; and
- **Open safe mode** enters the compiled `?safe=1` launcher.

Unavailable commands are disabled with a direct reason. No voice, attachment,
extension, product connection, or general capability control is shown merely
as a promise.

### Model picker

The native select is replaced with an accessible popover list. It provides:

- `Auto · via Pi` as the default;
- each authenticated model's public name and provider;
- visible selected state;
- keyboard navigation and Escape dismissal;
- outside-click dismissal;
- bounded height with scrolling for large model sets; and
- a setup-aware empty state rather than an empty control.

Model selection continues to use the existing session controller and Pi
runtime boundary. The picker receives public `ModelSummary` values only.

### Protected boundary

The composer remains compiled shell UI. A shaped document may position or
replace its own prompt node, but the shell still renders the protected
composer when no prompt node exists. React owns only ephemeral draft, menu,
focus, and layout state. Interface revisions, proposal state, persistence,
rollback, and safe mode continue to enter through the existing Effect
capabilities; the composer does not create a parallel shaping architecture.

## Media

All release media is generated after the production browser build passes its
tests.

### Screenshots

Playwright captures deterministic production screenshots at 1716 × 916:

- the default launcher with the final composer; and
- a validated interface proposal open in the Shaper workflow.

The fake test runtime is permitted because it exercises the same public
browser contracts and prevents model credentials, prompts, or provider output
from entering tracked artifacts. The screenshots must contain no personal
paths, account names, credentials, or private provider data.

### Demo

A concise, silent demo records the observable browser flow:

1. enter an interface change;
2. open the Interface Shaper;
3. propose the change;
4. preview it;
5. keep it; and
6. open the accepted interface after reload.

The source recording is WebM from Playwright. The README embeds a small looping
animated WebP derived from that recording, while the GitHub Release carries
the higher-quality MP4. The animation has no flashing content, starts from a
useful poster frame, and stays small enough not to dominate repository load.

### Repository hero

The final 1716 × 916 hero is composed deterministically from:

- the approved analytics dashboard image;
- the approved research dashboard image; and
- the final launcher screenshot.

The canvas stays light. `Flect` and `The interface that takes your shape.`
retain generous space on the left. The three surfaces are stacked on the
right with restrained radii and structural shadows, and intentionally continue
past the canvas edge. The final launcher is the foreground surface. The HTML
composition remains tracked so the raster can be reproduced when the product
changes.

## Installation and release

### Version

The public version is `0.1.0` in:

- `package.json`;
- `src-tauri/Cargo.toml`; and
- `src-tauri/tauri.conf.json`.

The Git tag and release name are `v0.1.0`.

### Browser/source quickstart

The README gives one copyable path:

```bash
git clone https://github.com/akua-dev/flect.git
cd flect
bun install
bunx pi
```

The person runs `/login` inside Pi, completes a supported provider login, quits
Pi, and starts Flect with:

```bash
bun run dev
```

The README explains that this starts Vite on `127.0.0.1:5173` and the
origin-restricted local Pi runtime on `127.0.0.1:3210`.

### macOS quickstart

The first binary package supports Apple Silicon and macOS 12 or newer. The
release contains:

- `Flect_0.1.0_aarch64.dmg`;
- `Flect_0.1.0_aarch64.dmg.sha256`; and
- `flect-v0.1.0-demo.mp4`.

The app is ad-hoc signed because this environment has no Developer ID
Application identity or notarization credentials. The README and release notes
state that boundary directly and include the smallest explicit recovery for
macOS quarantine. They do not describe the build as notarized, trusted by
Gatekeeper, or production-distributed.

Future releases can add Intel, Windows, Linux, Developer ID signing,
notarization, and updater support after those build and trust paths are
implemented and verified.

## README structure

The README is a concise public entry point in this order:

1. final hero and product sentence;
2. a release status line naming the protected v0.1 slice;
3. **Install Flect** with macOS download and browser/source paths;
4. the embedded real demo;
5. two real screenshots;
6. **What works today**;
7. the explicit current security and signing boundary;
8. architecture and vision links;
9. contributor verification; and
10. license.

It does not duplicate the full product vision, architecture, trust model, or
future roadmap.

## Verification

The exact release commit must prove:

- component tests cover the composer draft, keyboard, menu, model, send, stop,
  unavailable, and compact behavior;
- production Chromium tests cover the complete public composer and shaping
  workflows without console, page, or local request failures;
- screenshot and demo generation are deterministic and redact private data;
- `bun run check:all` passes;
- the Pi smoke completes a real private turn when provider/network access is
  available, or remains explicitly unverified rather than being folded into
  the offline deterministic gate;
- the DMG installs and its app launches with the private sidecar;
- the installed exact bundle is exercised through model discovery and at least
  one safe observable workflow;
- a Luna xhigh no-mistakes run reviews the final exact release commit;
- `main` resolves to that reviewed commit;
- tag `v0.1.0` resolves to the same commit; and
- every GitHub Release asset downloads and matches its recorded checksum.

## Delivery order

1. Implement the composer test-first.
2. Inspect and polish it in production Chromium at desktop and compact sizes.
3. Capture screenshots and demo from that verified build.
4. Recompose and inspect the hero.
5. Add packaging, versioning, quickstarts, and release notes.
6. Run deterministic and private smoke verification.
7. Run Luna xhigh no-mistakes on the exact release commit.
8. Build, install, and dogfood the final bundle.
9. Push that commit to `main`, create `v0.1.0`, and publish the release.
10. Download the public artifacts and verify them independently.
