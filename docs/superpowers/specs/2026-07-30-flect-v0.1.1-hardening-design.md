# Flect v0.1.1 Trust-Boundary Hardening

## Context

Flect v0.1.0 is published and immutable. Its final Luna review identified two
remaining trust-boundary failures:

1. A persisted `proposed` revision is reconciled to `previewed` during kernel
   startup, but the repair write can fail and prevent the `ShapingKernel`
   service from being constructed. The launcher then falls back visually
   without retaining a working kernel or recovery action.
2. Recursive `InterfaceDocument` schemas decode untrusted trees before the
   iterative depth and node checks run. A deeply nested shape request or
   revision journal can therefore exhaust the JavaScript stack before Flect
   returns its typed invalid-document result.

These are patch-release defects, not roadmap features. Flect v0.1.1 fixes them
without changing the user-facing interface or broadening v0.1 capabilities.

## Release decision

The published `v0.1.0` tag and assets remain unchanged. The fixes ship as
`v0.1.1`, become the latest GitHub Release, and update README install links.
This preserves release immutability and gives existing users an auditable
upgrade.

## Startup recovery

The kernel continues to reconcile a persisted `proposed` revision into a
visible in-memory `previewed` revision. Its startup repair write becomes
best-effort: `InterfaceStorageError` is contained at this one reconciliation
boundary instead of failing the layer.

The in-memory preview keeps the protected launcher, proposal controls, and
`/?safe=1` route reachable. Normal propose, preview, keep, reject, rollback,
safe-mode, and extension transitions remain transactional: their state changes
still require persistence to succeed. Flect does not silently weaken durable
transitions generally.

## Bounded document decoding

`validateInterfaceDocument` performs an iterative structural preflight before
the recursive Effect schema decoder. The preflight walks only the recursive
`root`/`children` graph, rejects cycles, rejects more than 100 nodes, rejects
more than 30 children per stack, and rejects depth above 10. It never recurses.
The existing schema remains the authority for field types, exact properties,
text limits, IDs, and supported actions.

All untrusted entry points must pass through that preflight before any schema
that embeds `InterfaceDocument` can recurse:

- direct interface validation;
- individual revision validation;
- active, last-known-good, and proposal documents in revision journals;
- browser HTTP shape requests; and
- native Effect RPC shape payloads.

HTTP request bodies and native RPC payloads therefore receive the document as
`unknown` first. Their handlers call `validateInterfaceDocument` before passing
the typed document to `FlectRuntime.shape`. Trusted responses retain the
existing typed `InterfaceDocument` schema.

## Failure behavior

- Invalid or over-limit documents fail with `InvalidInterfaceDocument`.
- Invalid journals fail with `InvalidRevision` and enter the existing recovered
  safe state.
- Invalid HTTP shape requests return the existing generic HTTP 400 response.
- Invalid native shape payloads return the existing typed runtime error.
- Storage-unavailable startup preserves a working protected shell and visible
  preview; it does not claim that the repair was durable.

## Verification

Tests must first reproduce both failures:

- a pending proposal plus a failing repository write must currently make the
  persistent kernel layer fail;
- a thousands-level raw stack tree must currently produce an Effect defect or
  overflow instead of the expected typed error.

The patch then proves:

- startup exposes the reconciled preview despite the failed repair write;
- direct, journal, HTTP, and native inputs reject deep trees without defects;
- normal valid documents and shape requests remain accepted;
- the full deterministic, browser, Rust, native package, Pi, and media gates
  remain green; and
- the exact v0.1.1 GitHub assets are downloaded and independently verified
  after publication.
