# Flect MVP implementation plan

Date: 2026-07-29

## Goal

Build a polished local Flect launcher that discovers authenticated models
through Pi, creates protected tool-free sessions, streams responses, and
retains a built-in recovery surface. Effect is the application architecture
across the shared, Bun, and browser layers; React owns rendering.

## Required development guidance

- Read `AGENTS.md`, `VISION.md`, `ARCHITECTURE.md`, and `CONTRIBUTING.md`.
- Read `.agents/skills/effect-ts/SKILL.md` and every reference it routes to
  for the capability in scope.
- Run `bun run prepare` if `.repos/effect` is missing, then verify APIs against
  that exact canonical source checkout.
- Use test-driven development and `@effect/vitest` for Effect behavior.
- Keep Effect dependencies on one exact version and install only packages
  required by implemented capabilities.

## Architecture

```text
React rendering
      |
      v
ManagedRuntime + browser Layers
      |
      v
Effect BrowserHttpClient / Stream
      |
      v
loopback Effect HttpRouter + BunHttpServer
      |
      v
FlectRuntime Context.Service
      |
      v
PiRuntime Context.Service / Pi SDK
```

- Shared Effect Schema classes define request, response, event,
  interface-document, and public-error contracts.
- Pi and application capabilities are `Context.Service` definitions with
  named production and test Layers.
- finite workflows use `Effect`; agent events and SSE bodies use `Stream`.
- resource lifetimes use Scope and finalizers.
- the Bun program and React host are the only places Effects are executed.
- tagged expected errors remain in the error channel and are deliberately
  mapped to public failures.
- structured logs and spans exclude prompts, responses, provider payloads,
  authentication state, and credentials.

## Global product and safety constraints

- Bind the local runtime to `127.0.0.1:3210`.
- Pi remains the only model/provider credential owner.
- Browser code never imports Pi or calls providers directly.
- Initial Pi sessions use `noTools: "all"` and in-memory session storage.
- Invalid customized state fails closed to the compiled launcher.
- `?safe=1` bypasses customized state and user extensions.
- Do not execute generated JavaScript or third-party extensions in the MVP.
- Preserve unselected visual assets in the parent checkout.
