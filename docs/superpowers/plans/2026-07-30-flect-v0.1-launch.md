# Flect v0.1 Launch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Flect v0.1.0 as a usable Apple Silicon macOS preview and
browser/source release with a T3-informed composer, real product media,
verified packages, and a public GitHub Release.

**Architecture:** Keep the existing Effect application kernel and Pi runtime
boundary unchanged. React owns ephemeral composer and popover interaction
state, while existing Effect snapshots and services continue to own shaping,
rollback, persistence, recovery, and provider operations. Generate repository
media from the deterministic production Playwright runtime only after the
product workflow passes.

**Tech Stack:** Effect 4 beta, React 19, TypeScript 7, Vite 8, Bun 1.4, Pi
0.82.1, Tauri 2, Rust, Vitest, Testing Library, Playwright, HTML/CSS media
composition, ffmpeg, GitHub Releases.

## Global Constraints

- Keep every installed Effect package exactly at `4.0.0-beta.102`.
- Keep Pi packages exactly at `0.82.1`.
- Keep browser code free of Pi imports, provider credentials, native process
  access, and direct model-provider calls.
- Keep interface proposal, persistence, rollback, and safe mode behind the
  existing Effect shaping capabilities.
- Keep React state limited to drafts, popovers, focus, and measured layout.
- Expose only actions that work in the current protected slice.
- Target Apple Silicon and macOS 12 or newer for the v0.1.0 binary package.
- Describe the macOS build as ad-hoc signed and unnotarized.
- Do not claim arbitrary UI import, `.flect` capsules, product/API
  capabilities, native extension execution, signing, or sharing are shipped.
- Capture no personal paths, account names, credentials, provider output, or
  private prompts in tracked media.
- Use the exact final reviewed commit for the installed app, `main`, tag
  `v0.1.0`, and all release artifacts.

- [ ] **Step 3: Implement the action menu with native popover semantics**

```tsx
export function ComposerActionsMenu(props: ComposerActionsMenuProps) {
  const [open, setOpen] = useState(false)
  const triggerRef = useRef<HTMLButtonElement>(null)

  const close = () => {
    setOpen(false)
    queueMicrotask(() => triggerRef.current?.focus())
  }

  return (
    <div className="composer-menu">
      <button
        aria-expanded={open}
        aria-haspopup="menu"
        aria-label="Actions"
        className="composer-control composer-control--icon"
        disabled={props.disabled}
        onClick={() => setOpen((current) => !current)}
        ref={triggerRef}
        type="button"
      >
        <AddIcon />
      </button>
      {open && (
        <div aria-label="Flect actions" className="composer-popover" role="menu">
          <button role="menuitem" onClick={() => { close(); props.onOpenShaper() }}>
            Shape interface
          </button>
          <button
            disabled={!props.rollbackAvailable || props.rollbackDisabled}
            role="menuitem"
            onClick={() => { close(); void props.onRollback() }}
          >
            Roll back last change
          </button>
          <button role="menuitem" onClick={() => { close(); props.onOpenSafeMode() }}>
            Open safe mode
          </button>
        </div>
      )}
    </div>
  )
}
```
